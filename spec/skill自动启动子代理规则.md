# skill自动启动子代理规则

skill应该可以自动启动子代理完成报告


## 主代理

主代理负责工作流中的
1. Identify the target project root, report title, student metadata if provided, and desired output directory.
2. Read the project files needed to understand goals, features, architecture, code structure, core logic, runtime environment, and tests.
3. Create `tmp/course-report-facts/` in the target project and write these files:
   - `01-project-overview.md`
   - `02-requirements-analysis.md`
   - `03-system-design.md`
   - `04-implementation-analysis.md`
   - `05-testing-evidence.md`
   - `06-report-evidence-map.md`
然后进行分工，将任务分发给子代理完成


## 报告写作代理A
该代理负责攥写报告的文案，需要参考上面的项目文档，表述风格约束，以及写作规范
1. 在攥写 `1. 选题背景` 时，根据项目内容和目标，编写一个恰当的项目背景，说明本项目应解决的主要问题及应达到的技术要求，简述本设计的指导思想。
2. 在攥写 `2. 方案论证(设计理念)` ..：说明设计原理（理念）并进行方案选择，阐明为什么要选择这个设计方案以及所采用方案的特点。包括：
      - 需求分析思路说明：需要有对系统要实现的功能和目标总的概括、报告中必须有规范的用例图、系统功能结构图说明系统功能、用户活动图分析用户操作流程、时序图说明系统关键功能执行时的时间序列、需要有对系统边界的约束和规范，系统的安全性、数据的完整性、应用的运行环境及其性能等要求。
      - 系统设计思路说明：报告中必须阐述为了实现需求，系统的架构是如何设计的，系统的技术栈是如何选择的，系统的顶层，一层，二层数据流是什么样的，系统的的包图说明系统的代码结构是什么样的，类图说明类和对象是如何设计的
       - 上述正文放到 "二、方案论证(设计理念)" 下方
3. 过程论述：重点说明设计是如何实现的，要求层次分明、表达确切。每个图都必须有文字说明，图前说明为什么使用该图、图的主要作用；图后说明图中各成分的作用，和成分之间的交互或图所表达的流程。包括
     - 系统实现思路的说明：报告中必须阐述代码实现的思路是什么样的，结合算法流程图阐述清楚核心功能代码的实现思路和关键逻辑代码

4. 结果分析：包括
     - 系统测试的思路说明：报告中必须阐述项目测试的方法以及目的，并附上测试结果，和结果说明。

（这个代理的职责是将报告内容写得内容详实，逻辑通顺，不画图只负责写文字和表述，产出报告并列出需要绘制的图像，然后输出报告给 UML图绘制代理B，和D2绘图代理C，再次强调这里的代理负责的是将报告内容写详实，怎么写才算详实我在上面写的提示词还不够准确，需要你来补充各个章节的具体写作要求，约束报告写作代理A进行写作）
... 

## UML图像绘制代理B
这个代理的职责是根据代理A的列出的需要的图像，然后根据相关的规范进行绘制美观符合要求的UML图，并一个文档汇总每个图的绘制情况和图要表达的信息，注意这个代理不绘制需要使用D2的图，这里对代理B的提示词仍然不够充分，需要你来进一步补充代理B的职责和边界

## D2绘图代理C
负责绘制代理A列出的，需要使用D2绘制的图，并将图产出到指定目录，注意这个代理不需要绘制UML图，并一个文档汇总每个图的绘制情况和图要表达的信息，这里对代理C的提示词仍然不够充分，需要你来进一步补充代理C的职责和边界


## 测试截图代理D
这个代理专门跑项目进行完整测试并详细记录测试结果（截图），并输出测试结果文档，不绘制UML图和D2图，这里对代理D的提示词仍然不够充分，需要你来进一步补充代理D的职责和边界

## 图像质量检验代理E

负责根据定义的规范，检验代理B，C，D生产的图像，检查图像是否合格，并产出检验报告，给出图像不合格的原因，并指导相关代理重新绘制截图，如果所有图像的质量都通过，交给代理F进行最后收尾，这里对代理E的提示词仍然不够充分，需要你来进一步补充代理E的职责和边界


## 汇总产出代理F
这个代理的任务是汇总上面B，C，D，代理的阐述，在报告加入图像，优化报告整体阐述风格，并将最终报告写入到docx（代理A只产出md格式），并进行最后的检验，这里对代理F的提示词仍然不够充分，需要你来进一步补充代理F的职责和边界


## 验收标准

- 在skill中每种代理都有自己的职责文档，工作方式工作边界，需要参考的资料，执行的标准和尊则，最终达到停止的标准和没达到标准的处理手段
- 在SKILL.md 中明确阐述需要多个代理合作完成报告撰写
- 实际使用skill的时候agent必须可以使用多个子代理完成任务，代理之间职责分明
