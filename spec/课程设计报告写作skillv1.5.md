# 课程设计报告撰写skillv1.4

此报告是在实际使用上个版本skill(由[课程设计报告撰写skillv1.4.md](课程设计报告撰写skillv1.4.md)指导制作的skill)后发现问题而提出的新需求文档


## 新增需求

报告写完之后出现了一些问题
1. DOCX 渲染检查尝试运行了 render_docx.py，但当前环境找不到 LibreOffice/soffice，所以未能完成 DOCX 转 PNG 的视觉级 QA,需要修复该脚本
2. 需要新增一个 报告初稿审查代理I： 在 报告写作代理A 完成草稿之后审查代理A给出的草稿，有没有满足基本的要求，代理A给出的内容是否足以阐述清楚课程设计项目的内容，要不要新增章节，图和阐述，保证报告内容丰富实在，可以准确阐述思路，没有漏图缺失信息。
3. 最终课程设计报告，文字阐述不够详实，主要是对图的阐述，需要新增一个 报告文案增强代理H，他的职责是在`交付检查智能体G`和`汇总产出代理F`执行之前，完成报告文字的润设，不检查图像，不检查格式，仅仅专注于报告文案本身，需要逐一审查各个章节的报告撰写质量,需要站在教授的角度对报告内容进行评判并进行修改
   1. 一、选题背景: 有没有阐述清楚本课题的背景，需要解决的主要问题和技术要求，逻辑是否连贯正确，有没有正确表达清晰，表达是否出现逻辑错误和上下文不匹配
   2. 二、方案论证(设计理念)： 
      - 有没有先说清楚课题提出了哪些需求，是如何分析这些需求的，图有没有很好的契合当前的表述，是否太简短没有说清楚分析的思路和逻辑，图的出现是否突兀，
      - 有没有阐述清楚从需求用例，如何提取出系统需要实现的功能的，图的阐述有没有帮助读者理解这个图的意图和分析的思路。
      - 拆分系统组件的时候有没有阐述清楚这样拆分的逻辑和思路，避免直接放图没有思路说明和阐述；
      - 在放活动图之前，有没有先阐述清楚为什么要分析用户的行为，要分析用户的哪些活动，分析这个活动的目的是什么，接下来才引出绘制的活动图，并阐述图的帮助读者理解，并进一步阐述下一步分析的思路
      - 在展示时序图之前有没有先阐述清楚，为什么要画时序图，原因是什么，分析的思路是什么，放图之后有没有追加阐述，并引出下一步分析的思路
       - 其他内容也是一样的要先阐述清楚，为什么，分析的思路， 放图之后有没有追加阐述，并引出下一步分析的思路
   3. 三、过程论述 ：同样的和二一样，要反思阐述的意义和是否将实现的思路表达清晰。
   4. 四、结果分析： 开头写清楚，做了哪些测试，为什么做，测试的思路是什么，最后结果是什么样的，有没有符合预期，不是单纯的列出结果。
   5. 五、课程设计总结：有没有先讲清楚做了什么，有没有写清楚课程设计过程的收获、遇到的问题，遇到问题解决问题过程的思考、程序调试能力的思考，课程设计实现过程中的收获和体会等。
4. 生成产物后原本word文档中的 `课题名称`占位文字没有删掉，需要限制智能体在填充报告后检查，将模板残余去除
