# 课程设计报告撰写skillv1.4

此报告是在实际使用上个版本skill(由[课程设计报告撰写skillv1.3.md](课程设计报告撰写skillv1.3.md)指导制作的skill)后发现问题而提出的新需求文档


## 新增需求

报告写完之后出现了一些问题
1. 最后收尾的代理在检验时出现偷懒，报告中出现 "图中内容均来自项目的 ...", 这样的表述，却没有修正和说明，需要在skill中再添加一个子代理，在 `汇总产出代理F` 产出后做最后的全面审查和修正产物。
2. 首先是最终产物没有保证5个标题是首行缩进两字符的，'课题名称'前面没有各空一行，需要增强相关文档，提示代理检验和修复这个漏洞
3. 产出结果将报告追加到4页之后，3，4页中残留多余的模板没有清除，需要编写验收规则限制最后
4. 即使没有参考文献，报告最后也要有参考文献部分，但是具体文献要留空，添加这条规则到相关文件
5. 交付产物中图片前多次出现 “为说明系统组件图所对应的设计内容，报告插入如下图示。” 这样的阐述，过于僵硬不够通顺自然，可以表述为“根据原始需求，可以分析出系统具有以下用例”，应该阐述清楚报告这里要表达什么，不是为了画图而画图，而是有逻辑的说明设计上我们分析的思路是什么，配图只是思维阐述的一个增强，在书写报告文案的时候应该让agent更注重设计的思路和逻辑，将清楚要做什么，为什么，怎么做，做完之后的结果展示，在撰写说明相关文档添加规矩，告诉智能体如何表达通顺，避免僵硬，同时注意内容详实，并要求相关智能体完成后做相关的检查和校验。


## 验收标准
1. 必须添加新的交付检查智能体G，写清楚智能体的职责，并让智能体检查，表达内容是否违规，报告表达逻辑是否通顺，最终报告格式是否正确，如果发现文件就修复交付产物
2. 必须保证最终产物解决了5个标题没有首行缩进两字符，原本模板残留没有去除的问题，即使项目没有参考文件报告最后还是要有参考文献的结构，同时不能出现其他格式问题
3. 必须强调报告表述问题，要对智能体进行限制使用 “为说明系统组件图所对应的设计内容，报告插入如下图示。” ，"图中内容均来自项目的 ..."这样的阐述，在图片上方的阐述必须起承上启下的作用，语义连贯不僵硬。
